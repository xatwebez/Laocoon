# Laocoön 拉奥孔 · 窗口探针

**中文** · [English](docs/README.en.md) · [Русский](docs/README.ru.md) · [Français](docs/README.fr.md) · [Español](docs/README.es.md) · [العربية](docs/README.ar.md) · [Deutsch](docs/README.de.md) · [Português](docs/README.pt.md) · [日本語](docs/README.ja.md) · [한국어](docs/README.ko.md) · [हिन्दी](docs/README.hi.md) · [Italiano](docs/README.it.md)

> 特洛伊城下，所有人都急着把那匹木马拖进城，只有拉奥孔不信。
> 他一矛捅进马腹 —— 里面传出兵器相撞的金属声。
>
> 这个工具做的是同一件事：**戳一下窗口，听里面藏着什么。**

<p align="center">
  <img src="docs/img/laocoon.gif" width="640" alt="一匹带轮子的木马被准星戳中腹部，裂口里露出三个窗口，其中一个标着红点">
</p>

看到一个不认识的（可能是流氓软件）窗口，按一下 `F2`，把准星拖上去，左键点击，它会把那个窗口和它背后那个进程能扒出来的信息全部列出来。

- 单文件 `Laocoon.exe`，约 **208 KB**
- 零第三方依赖，只用 Windows 自带的 .NET Framework 4.x（Win10 / Win11 系统自带，无需安装任何东西）
- 不联网、不上传、不写注册表、不落任何配置文件、不留驻后台（解压即用，跑完磁盘上不留任何东西）
- 十二种语言内置：**中文 / English / Русский / Français / Español / العربية / Deutsch / Português / 日本語 / 한국어 / हिन्दी / Italiano**

> 文件名用 ASCII 的 `Laocoon.exe`，界面和标题栏里保留带分音符的 `Laocoön 拉奥孔`。
> 这样路径、命令行、邮件附件、CI 里都不会因为非 ASCII 字符出岔子。

## 用法

<p align="center">
  <img src="docs/img/detect.gif" width="640" alt="按下 F2 后准星套住窗口，底部升起报告，同进程的三个窗口里有一个是隐藏的">
</p>

1. 双击 `Laocoon.exe`（想拿到最全的信息，**右键 → 以管理员身份运行**）
2. 按 `F2`，鼠标变成十字准星
3. 把鼠标移到目标窗口上 —— 会有蓝框圈住它，旁边浮着一个小黑框，实时显示类名 / 标题 / PID / 父窗口
4. **左键**锁定并采集；**右键**或 **Esc** 取消
5. 结果直接出现在窗口里 —— 完整报告、疑点提示，一次列全

采集是一次性的：不会定时刷新、不会挂在后台盯着你，关掉窗口就什么都不剩（除了你自己点「保存报告」写出去的那个文件）。

这 12 种是这么挑的：联合国安理会五常的语言打底，再补上**阿拉伯语**（联合国六种工作语言里唯一被漏掉的那个）、
**德语 / 葡萄牙语 / 日语 / 韩语**（主要经济体和软件生态）、**印地语**（人口最大的单一语言市场）、
**意大利语**（欧洲文化圈）。土耳其语、印尼语、越南语、波兰语这些没有加——留了扩展位，加一种只要在 `Lang.cs` 里补一张表。

首次运行按下面的顺序决定语言：

```
命令行 --lang=xx  >  系统界面语言  >  英语
```

也就是中文系统默认中文，俄/法/西/阿/德/葡/日/韩/印/意语系统各自显示自己的语言，其余语言环境回落到英语
（`pt-BR`、`zh-Hant`、`ar-EG` 这类带地区的写法都能识别）。切换只在本次运行有效，程序不保存任何设置；想固定成某种语言，用 `Laocoon.exe --lang=ru` 启动（或建个带参数的快捷方式）。

翻译跟着一起走的还有**报告正文**——标签、章节标题、启发式提示（“可执行文件位于临时目录”“该进程另有 N 个隐藏的顶层窗口”）都是按当前语言生成的。

### 阿拉伯语（从右到左）是怎么处理的

阿拉伯语不是“换一套字符串”就完事的，有三个坑是实测踩出来的：

1. **界面镜像**：整个界面用 `RightToLeftLayout` 翻转，工具栏从右往左排，主按钮落在最右上。
2. **报告正文不镜像**：报告里是路径、哈希、窗口类名这类技术数据，跟着镜像会把一行的首尾掉过来。
   所以报告框永远保持从左到右，只有**说明页**（散文）在阿拉伯语下右对齐。
3. **冒号会跑到标签左边**：GDI 的 BiDi 认为“阿拉伯标签 + `:` + 拉丁值”里的冒号属于右侧的 RTL 段，
   渲染成 `0 :المقبضx0001048E`。解决办法是在冒号两侧插入零宽的 LRM（U+200E）强制方向归属，
   格式化参数（日期、PID、类名）也一并做方向隔离——否则日期会变成 `04:28:37 08-11-2026`。
   这套写法的对照实验留在 `--biditest` 诊断里，以后换实现可以直接重跑。

另外**印地语天城文**和阿拉伯文一样没有固定字宽，“补空格对齐”只会越补越歪，
所以这两种语言的报告改用 `标签: 值` 的写法，宁可不对齐也不假装对齐。
阿拉伯语、印地语、日语、韩语的界面字体各自使用系统自带的那一套（Segoe UI / Nirmala UI / Yu Gothic UI / Malgun Gothic），
没有装的语言会自动回落，不会出现方块或抛异常。

## 采到了什么

| 分类 | 内容 |
|---|---|
| 窗口 | 句柄、类名、标题、窗口样式位（解码成 `WS_*` / `WS_EX_*` 名字）、位置尺寸、客户区、是否可见/最小化、**是否置顶**、**是否工具窗口**、**是否被 DWM 隐身**、属主窗口 |
| 命中控件 | 准确到子控件：类名、控件 ID、控件文本、自根窗口到该控件的层级路径 |
| 进程 | PID / TID、完整路径、**命令行**、父进程（名字+PID）、架构（x86 / x64 / WOW64）、**是否已提权**、会话、启动时间 |
| 文件 | 大小、创建/修改时间、**MD5 / SHA1 / SHA256**、公司、产品、描述、文件版本、版权 |
| 数字签名 | 有无内嵌签名、签名者、颁发者、有效期、链校验结果 |
| 模块 | 该进程加载的全部 DLL 完整路径 |
| 同进程窗口 | 该进程**所有**顶层窗口，包括隐藏的（`[隐藏]` 标记）——流氓软件的后台窗口藏不住 |
| 子控件树 | 目标窗口的整棵子控件树，带缩进、尺寸、控件 ID、控件文本 |
| 疑点提示 | 启发式标注：落在 Temp/下载/AppData、无签名、无公司名、置顶、隐藏窗口个数、文件创建于 7 天内等（**只是提示，不是结论**） |

整份报告是纯文本：标签对齐、分节清晰，可以全选复制，也可以「保存报告」存成 UTF-8 的 `.txt`。
想再核对某个文件，把报告里的 `sha256` 复制到任何你信任的地方比对即可 —— 这个工具只做本地采集，不联网、不上传。

## 已知限制

- **数字签名**只检测 PE 内嵌签名。系统自带文件（如 `notepad.exe`）走的是目录签名（catalog），这里会显示“未发现内嵌签名”，属正常。
- 非管理员运行时，对**已提权或受保护**的进程读不到路径/模块/命令行（会显示“权限不足”），其余字段照常。
- `WM_GETTEXT` 取控件文本时对无响应的窗口设了 60ms 超时（`SMTO_ABORTIFHUNG`），不会把界面卡死；但也正因为如此，极少数卡死的窗口读不到文本。
- 子控件树最多 240 项、模块最多 400 项，超出会标注“已截断”。
- 哈希上限 512 MB，超过则跳过（避免卡太久）。
- 界面语言跟系统走，12 种之外的环境回落到英语；翻译是人工写的，`WS_*` / `WS_EX_*`、`DWM Cloaked` 这类 Windows 专有术语刻意保留英文原文，免得译者各说一套反而看不懂。
- 阿拉伯语界面是镜像的，但**报告永远从左到右**——里面是技术数据，跟着镜像没法读。这是刻意设计，不是没翻全。

## 自己重新编译

需要 .NET SDK（8 或更高）。双击 `build.bat`，或者：

```bat
dotnet build src\Laocoon.csproj -c Release
```

产物在 `src\bin\Release\net48\Laocoon.exe`。

> `build.bat` 里特意把 `TEMP` 指到了本地 `.tmp` 目录，因为有些机器的系统临时目录不可写，会让构建直接失败。

## 源码

- `src/Laocoon.cs` —— 主程序，约 2225 行，全部 Win32 P/Invoke，没有任何 NuGet 包
- `src/Lang.cs` —— 语言核心（枚举、识别、字体、宽度、取词与回落）和 12 张文案表都在这一份文件里，约 2250 行
- `src/Laocoon.ico` —— 像素图标本身（16~256 共 8 个尺寸），由 `tools/make_icon.py` 用 16 格母版生成
- `docs/img/*.gif` —— README 里的两段像素动画，由 `tools/make_gifs.py` 逐帧程序化生成（8 色、160×90 网格、整数倍放大）

每张表 124 个键，全部编译进 exe，不生成 `.resources`、不生成 satellite assembly，
所以拷到任何一台 Win10/11 上都能直接用，不会出现“缺语言包退回英文”。

主要入口：
- `Probe.HitTest` —— 按 z 序自己遍历顶层窗口做命中测试（不依赖 `WindowFromPoint`，避免打到自己的覆盖层）
- `Probe.DeepestAt` —— 用 `ChildWindowFromPointEx` 逐层下钻到最内层控件
- `Probe.Collect` —— 汇总窗口/进程/文件/签名/模块/兄弟窗口/子控件树
- `FrameForm` / `HudForm` —— 瞄准时的透明蓝框和跟随 HUD（都是 `WS_EX_TRANSPARENT | WS_EX_NOACTIVATE`，不吃鼠标事件）
- `L.T` / `L.F` —— 取词和带占位符取词；缺失的键自动回落英语，不会显示成空白

## 诊断开关（看代码用，平时用不到）

```
Laocoon.exe --selftest out.txt    采集当前控制台窗口并打印报告，报告写入文件
Laocoon.exe --aimtest              自检命中测试与瞄准覆盖层
Laocoon.exe --i18ncheck            检查 12 种语言的键是否齐全、列宽/字体/方向是否正确
Laocoon.exe --langswitch           模拟逐个切换语言，检查界面文字和报告是否都跟着变
Laocoon.exe --focustest f.log [shot.png]  逐个切换 12 种语言，检查语言下拉框的焦点有没有被保住
Laocoon.exe --langstress 300 [log] [--rtl] 模拟按住方向键连发切换，检查句柄重建与资源是否稳定
Laocoon.exe --biditest out.png     阿拉伯文 + 拉丁数据混排的 8 种写法对照图（验证 BiDi）
Laocoon.exe --lang=ru              临时以指定语言启动（不写入 ini）
Laocoon.exe --uishot out.png --lang=ar            渲染界面截图
Laocoon.exe --uishot out.png --lang=ar --welcome  只渲染说明页
Laocoon.exe --uishot out.png --lang=ar --screen   改用屏幕抓取（DrawToBitmap 对 RTL 文本框会画出假选区）
```

自检用 `--lang=` 配合截图时，能一次渲染全部 12 种语言的界面做视觉核对。
