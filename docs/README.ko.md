# Laocoön · 창 프로브

[中文](../README.md) · [English](README.en.md) · [Русский](README.ru.md) · [Français](README.fr.md) · [Español](README.es.md) · [العربية](README.ar.md) · [Deutsch](README.de.md) · [Português](README.pt.md) · [日本語](README.ja.md) · **한국어** · [हिन्दी](README.hi.md) · [Italiano](README.it.md)

> 트로이 성문 앞에서 모두가 그 목마를 성 안으로 끌어들이려 했다. 라오콘만은 믿지 않았다.
> 그는 창을 말의 배에 찔러 넣었고 — 안에서 무기 부딪히는 쇳소리가 들려왔다.
>
> 이 도구가 하는 일도 같다: **창을 찔러 보고, 안에 무엇이 숨었는지 듣는다.**

</p>

낯선 창이 보인다 — 어쩌면 원치 않는 프로그램일지도 모른다. `F2`를 누르고 십자 조준선을 그 위로 옮긴 뒤 클릭하라. 그 창과 그 뒤의 프로세스에서 뽑아낼 수 있는 정보를 전부 늘어놓는다.

- 단일 파일 `Laocoon.exe`, 약 **208 KB**
- 서드파티 의존성 없음. Windows에 기본 포함된 .NET Framework 4.x만 사용 (Win10 / Win11이면 설치할 것이 없음)
- 네트워크 연결 없음, 업로드 없음, 레지스트리 쓰기 없음, 설정 파일 없음, 상주 없음 (압축을 풀어 실행하면 디스크에 아무것도 남지 않는다)
- 12개 언어 내장: **中文 / English / Русский / Français / Español / العربية / Deutsch / Português / 日本語 / 한국어 / हिन्दी / Italiano**

> 파일 이름은 ASCII `Laocoon.exe`, 창 제목에는 분음부호가 있는 `Laocoön`을 그대로 둔다.
> 그래야 경로, 명령줄, 메일 첨부, CI 어디에서도 비 ASCII 문자로 걸리지 않는다.

## 사용법

<p align="center">
  <img src="img/detect.gif" width="640" alt="F2를 누르면 조준선이 창을 잡고 아래에서 보고서가 올라온다. 그 프로세스의 창 세 개 중 하나는 숨겨져 있다">
</p>

1. `Laocoon.exe`를 더블클릭 (가장 자세한 정보를 얻으려면 **오른쪽 클릭 → 관리자 권한으로 실행**)
2. `F2`를 누르면 커서가 십자 조준선으로 바뀐다
3. 대상 창 위로 이동 — 파란 테두리가 그 창을 감싸고, 옆에 작은 검은 HUD가 떠서 클래스명 / 제목 / PID / 부모 창을 실시간으로 보여준다
4. **왼쪽 클릭**으로 고정하고 수집, **오른쪽 클릭**이나 **Esc**로 취소
5. 보고서 전체가 곧바로 표시된다. 창, 프로세스, 파일, 서명, 숨은 창과 자식 컨트롤까지 한 번에

수집은 한 번뿐이다. 주기적으로 갱신하지도, 뒤에서 상주하며 지켜보지도 않는다. 창을 닫으면 아무것도 남지 않는다 — 직접 "보고서 저장"을 눌러 쓴 파일만 빼고.

이 12개를 고른 이유: 유엔 안전보장이사회 상임이사국 5개국의 언어를 토대로, **아랍어**(유엔 6개 공용어 중 그 목록에서 빠진 유일한 언어), **독일어 / 포르투갈어 / 일본어 / 한국어**(주요 경제권과 소프트웨어 생태계), **힌디어**(인구 기준 최대 단일 언어 시장), **이탈리아어**(유럽 문화권)를 더했다. 튀르키예어, 인도네시아어, 베트남어, 폴란드어는 넣지 않았다 — 확장 지점은 열어 두었고, 한 언어를 더하려면 `Lang.cs`에 표 하나를 추가하면 된다.

첫 실행 시 언어는 다음 순서로 정해진다:

```
명령줄 --lang=xx  >  시스템 표시 언어  >  영어
```

즉 중국어 시스템은 중국어로, 러시아어 / 프랑스어 / 스페인어 / 아랍어 / 독일어 / 포르투갈어 / 일본어 / 한국어 / 힌디어 / 이탈리아어 시스템은 각자의 언어로 시작하고, 나머지는 영어로 떨어진다(`pt-BR`, `zh-Hant`, `ar-EG` 같은 지역 표기도 인식한다). 전환은 이번 실행에만 적용되고 설정은 저장되지 않는다. 언어를 고정하려면 `Laocoon.exe --lang=ru`로 실행하거나 그 인수를 넣은 바로가기를 만들면 된다.

번역되는 것은 화면만이 아니다. **보고서 본문**도 마찬가지여서 레이블, 절 제목, 휴리스틱 주의 문구("실행 파일이 임시 폴더에 있음", "이 프로세스에 숨겨진 최상위 창이 N개 더 있음")가 현재 언어로 생성된다.

### 아랍어(오른쪽에서 왼쪽) 처리 방식

아랍어는 "문자열 표만 바꾸면 되는" 일이 아니다. 실측에서 세 가지 함정이 나왔다:

1. **화면 미러링**: 폼 전체를 `RightToLeftLayout`으로 뒤집고, 도구 모음은 오른쪽에서 왼쪽으로 흐르며, 주 버튼이 맨 오른쪽에 온다.
2. **보고서는 미러링하지 않음**: 내용이 경로, 해시, 창 클래스명 같은 기술 데이터라서 미러링하면 각 줄의 앞뒤가 뒤집혀 읽을 수 없다. 보고서 상자는 항상 왼쪽에서 오른쪽. 아랍어에서는 **환영 페이지**(산문)만 오른쪽 정렬된다.
3. **콜론이 레이블 왼쪽으로 튐**: GDI의 BiDi 엔진은 "아랍어 레이블 + `:` + 라틴 값"에서 콜론을 오른쪽 RTL 구간에 속한다고 보고 `0 :المقبضx0001048E`처럼 그린다. 해법은 콜론 양쪽에 폭 0인 LRM(U+200E)을 넣어 방향을 강제하는 것이고, 서식 인자(날짜, PID, 클래스명)에도 같은 격리를 적용한다 — 그러지 않으면 날짜가 `04:28:37 08-11-2026`이 된다. 이 표기법의 비교 실험은 `--biditest` 진단에 남겨 두었으니, 구현을 갈아엎어도 바로 다시 돌려 볼 수 있다.

**데바나가리(힌디어)** 역시 아랍어처럼 고정 폭이 없어서, "공백으로 채워 정렬"하면 오히려 더 어긋난다. 그래서 이 두 언어는 보고서를 `레이블: 값` 형식으로 바꾼다. 정렬된 척하는 것보다 안 맞는 편이 낫다.
아랍어, 힌디어, 일본어, 한국어는 각각 Windows에 들어 있는 글꼴(Segoe UI / Nirmala UI / Yu Gothic UI / Malgun Gothic)을 쓰고, 없으면 자동으로 대체된다. 두부 글자나 예외는 나오지 않는다.

## 무엇을 수집하나

| 분류 | 내용 |
|---|---|
| 창 | 핸들, 클래스명, 제목, 스타일 비트(`WS_*` / `WS_EX_*` 이름으로 해독), 사각형, 클라이언트 영역, 표시 / 최소화, **항상 위**, **도구 창**, **DWM 은폐**, 소유자 창 |
| 적중 컨트롤 | 자식 컨트롤까지 정확히: 클래스, 컨트롤 ID, 텍스트, 루트 창에서 그 컨트롤까지의 경로 |
| 프로세스 | PID / TID, 전체 경로, **명령줄**, 부모 프로세스(이름 + PID), 아키텍처(x86 / x64 / WOW64), **권한 상승 여부**, 세션, 시작 시각 |
| 파일 | 크기, 생성 / 수정 시각, **MD5 / SHA1 / SHA256**, 회사명, 제품명, 설명, 파일 버전, 저작권 |
| 디지털 서명 | 내장 서명 유무, 서명자, 발급자, 유효 기간, 체인 검증 결과 |
| 모듈 | 그 프로세스가 로드한 모든 DLL의 전체 경로 |
| 같은 프로세스의 창 | 그 프로세스의 **모든** 최상위 창, 숨겨진 것 포함(`[숨김]` 표시) — 원치 않는 프로그램의 뒷단 창은 여기서 숨을 수 없다 |
| 자식 컨트롤 트리 | 대상 창의 자식 컨트롤 전체. 들여쓰기, 크기, ID, 텍스트 포함 |
| 의심 신호 | 휴리스틱: Temp / 다운로드 / AppData에 위치, 서명 없음, 회사명 없음, 항상 위, 숨겨진 창 개수, 7일 이내 생성된 파일 등 (**힌트일 뿐 단정이 아님**) |

보고서는 전체가 일반 텍스트라 열이 맞고 절마다 구분되어 있다. 전체를 선택해 복사하거나 "보고서 저장"으로 UTF-8 `.txt` 파일로 쓸 수 있다. 파일을 더 확인하려면 `sha256`을 믿을 수 있는 곳에 복사해 비교하면 된다. 이 도구는 로컬에서만 수집하며 연결하거나 전송하지 않는다.

## 알려진 제한

- **디지털 서명**은 PE에 내장된 서명만 검사한다. Windows 자체 파일(`notepad.exe` 등)은 카탈로그 서명이라 "내장 서명 없음"으로 나오는데 정상이다.
- 관리자 권한 없이 실행하면 권한이 상승됐거나 보호된 프로세스에서 경로 / 모듈 / 명령줄을 읽지 못한다("권한 부족" 표시). 나머지 항목은 그대로 나온다.
- 컨트롤 텍스트를 가져오는 `WM_GETTEXT`는 응답 없는 창에 60ms 제한을 둔다(`SMTO_ABORTIFHUNG`). 화면이 멈추지 않는 대신, 아주 드물게 멈춘 창에서는 텍스트를 못 읽는다.
- 자식 컨트롤 트리는 최대 240개, 모듈 목록은 최대 400개이며, 넘으면 "잘림"으로 표시된다.
- 해시 계산은 512 MB까지. 그보다 크면 건너뛴다(오래 기다리지 않도록).
- 표시 언어는 시스템을 따르고, 12개 밖이면 영어로 떨어진다. 번역은 직접 쓴 것이며, `WS_*` / `WS_EX_*`, `DWM Cloaked` 같은 Windows 고유 용어는 일부러 영어로 남겼다. 언어마다 제각각 용어를 만들면 오히려 못 알아보기 때문이다.
- 아랍어 화면은 미러링되지만 **보고서는 항상 왼쪽에서 오른쪽**이다. 내용이 기술 데이터라 미러링하면 읽을 수 없다. 의도된 설계이며 번역이 덜 된 것이 아니다.

## 직접 빌드하기

.NET SDK(8 이상)가 필요하다. `build.bat`을 더블클릭하거나:

```bat
dotnet build src\Laocoon.csproj -c Release
```

결과물은 `src\bin\Release\net48\Laocoon.exe`.

> `build.bat`은 `TEMP`를 일부러 로컬 `.tmp` 폴더로 잡는다. 시스템 임시 폴더에 쓸 수 없는 환경에서는 빌드가 곧바로 실패하기 때문이다.

## 소스 구성

- `src/Laocoon.cs` — 본체. 약 2225줄, 전부 Win32 P/Invoke이고 NuGet 패키지는 하나도 쓰지 않는다
- `src/Lang.cs` — 언어 핵심(열거, 판별, 글꼴, 폭, 조회, 대체)과 12개 언어 표를 한 파일에. 약 2250줄
- `src/Laocoon.ico` — 픽셀 아이콘 자체(16~256, 8가지 크기). 16칸 격자에서 `tools/make_icon.py`로 생성
- `docs/img/*.gif` — 이 README의 픽셀 애니메이션 두 편. `tools/make_gifs.py`가 프레임마다 그린다 (8색, 160×90 격자, 정수배 확대)

표마다 124개 키이고 전부 exe에 컴파일된다. `.resources`도 satellite assembly도 만들지 않아서, 어떤 Win10/11 컴퓨터에서도 그대로 동작하고 "언어 팩이 없어 영어로 대체"되는 일이 없다.

주요 진입점:
- `Probe.HitTest` — z 순서로 최상위 창을 직접 훑어 히트 테스트한다(`WindowFromPoint`를 쓰지 않아 자기 오버레이를 잡지 않는다)
- `Probe.DeepestAt` — `ChildWindowFromPointEx`로 가장 안쪽 컨트롤까지 내려간다
- `Probe.Collect` — 창 / 프로세스 / 파일 / 서명 / 모듈 / 형제 창 / 자식 컨트롤 트리를 모은다
- `FrameForm` / `HudForm` — 조준할 때의 투명한 파란 테두리와 따라다니는 HUD(둘 다 `WS_EX_TRANSPARENT | WS_EX_NOACTIVATE`라 마우스를 가로채지 않는다)
- `L.T` / `L.F` — 문자열 조회와 자리표시자 서식. 없는 키는 영어로 대체되고 빈칸으로 남지 않는다

## 진단 스위치 (코드를 볼 때만)

```
Laocoon.exe --selftest out.txt     콘솔 창을 수집해 보고서를 출력하고 파일로 쓴다
Laocoon.exe --aimtest              히트 테스트와 조준 오버레이 자체 점검
Laocoon.exe --i18ncheck            12개 언어의 키 누락, 열 너비, 글꼴, 방향 검사
Laocoon.exe --langswitch           모든 언어를 차례로 바꿔 화면 문구와 보고서를 대조
Laocoon.exe --focustest f.log [shot.png]  12개 언어를 차례로 전환하며 목록이 포커스를 유지하는지 확인
Laocoon.exe --langstress 300 [log] [--rtl] 키 반복 전환을 재현해 핸들 재생성과 자원 안정성 확인
Laocoon.exe --biditest out.png     아랍어 + 라틴 데이터 혼용 8가지 배치 비교도 (BiDi 검증)
Laocoon.exe --lang=ru              지정 언어로 실행 (ini에 쓰지 않음)
Laocoon.exe --uishot out.png --lang=ar            화면을 PNG로 렌더링
Laocoon.exe --uishot out.png --lang=ar --welcome  설명 페이지만 렌더링
Laocoon.exe --uishot out.png --lang=ar --screen   화면 캡처로 전환 (DrawToBitmap은 RTL 상자에 가짜 선택 영역을 그린다)
```

`--lang=`과 함께 쓰면 12개 언어 화면을 한 번에 렌더링해 눈으로 확인할 수 있다.
