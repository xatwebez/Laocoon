> トロイアの城門前で、誰もがその木馬を城内へ引き入れようとしていた。ラオコーンだけが信じなかった。
> 彼は槍を馬の腹に突き立て —— 中から武器のぶつかる金属音が聞こえた。

## 少しだけ背景：彼はトロイアを救えなかった

ラオコーンはトロイアの祭司だった。木馬を疑い、その腹に槍を突き立て、焼き払うよう市民に説いた。

だが誰も説得できなかった。神々はギリシア側にいた。二匹の海蛇が海から現れ、浜辺で彼と二人の息子を絞め殺した。
トロイアの人々はそれを「神を冒涜した報い」と受け取り、かえって安心して木馬を城内へ引き入れた。夜、隠れていた兵士が門を開け、トロイアは陥落した。

これがこの物語でいちばんロマンのないところだ。**彼の判断は正しかった。だが誰にも信じさせられず、確かめられる日まで生きられなかった。**

この道具の立ち位置も、そこにある。あなたの代わりに判断せず、結論も出さない。ウィンドウとそのプロセスから読み取れるもの――パス、署名、読み込まれたモジュール、子コントロール、そして怪しいと思われるいくつかの箇所――を机の上に並べるだけだ。

どれが本当に怪しいのか、手を打つべきか、報告すべきか、今回は空振りだったのか。決めるのはあなた自身だ。この道具も間違える。「疑わしい点」はあくまで経験則であって、判決ではない。

レポートは事実の一覧であって、判決文ではない。よく見て、それから慎重に動いてほしい。

見覚えのないウィンドウ —— もしかすると望ましくないソフトかもしれない。`F2` を押し、十字の照準をその上に合わせてクリックする。そのウィンドウと、その背後にあるプロセスから引き出せる情報を全部並べる。

- 単一ファイル `Laocoon.exe`、約 **466 KB**
- サードパーティ依存ゼロ。Windows に最初から入っている .NET Framework 4.x だけを使う（Win10 / Win11 なら何もインストール不要）
- レジストリに書かず、設定ファイルも作らず、常駐もしない（解凍して実行、ディスクに何も残らない）
- 61 言語を内蔵：全量訳 12 言語＋操作 UI レベル 49 言語（レポート本文は英語のまま）
> ファイル名は ASCII の `Laocoon.exe`、ウィンドウタイトルは分音記号つきの `Laocoön` のまま。
> こうしておけばパス、コマンドライン、メール添付、CI のどこでも非 ASCII でつまずかない。

## 使い方

<p align="center">
  <img src="img/detect.gif" width="640" alt="F2 を押すと照準がウィンドウを捉え、下からレポートがせり上がる。そのプロセスの三つのウィンドウの一つは隠されている">
</p>

1. `Laocoon.exe` をダブルクリック（最も詳しい情報を得るなら **右クリック → 管理者として実行**）
2. `F2` を押すと、カーソルが十字の照準になる
3. 対象ウィンドウの上に移動 —— 青い枠がそのウィンドウを囲み、横に小さな黒い HUD が出て、クラス名 / タイトル / PID / 親ウィンドウをリアルタイムに表示する
4. **左クリック**で確定して採取、**右クリック**または **Esc** で中止
5. レポートはその場で全文表示される。ウィンドウ、プロセス、ファイル、署名、隠れたウィンドウ、子コントロールまで一度に

採取は一度きり。定期的に更新することも、背後で居座って監視することもない。ウィンドウを閉じれば何も残らない —— 自分で「レポートを保存」を押して書き出したファイル以外は。

この 12 言語の選び方：国連安保理常任理事国 5 か国の言語を土台に、**アラビア語**（国連の公用語 6 つのうち、その 5 か国から漏れている唯一の言語）、**ドイツ語 / ポルトガル語 / 日本語 / 韓国語**（主要経済圏とソフトウェア生態系）、**ヒンディー語**（人口最大の単一言語市場）、**イタリア語**（ヨーロッパ文化圏）を追加した。さらに 49 言語を**操作 UI レベル**で追加 — ヨーロッパ主要言語、中東と中央アジア、南アジアと東南アジア、アフリカの主要言語、plus エスペラント。ツールバー・バージョン情報・更新ダイアログ・ステータスバーは訳済みで、レポート本文と項目ラベル（Handle、Class、PID など）は英語のまま — 開発者ドキュメントではこれらの語は元々英語だからです。完全翻訳への格上げは `Lang.cs` の該当表を埋めるだけで、新しい言語の追加は `LangExtra.cs` に 1 行足すだけです。

ドロップダウンは**段付き**です。上から国連五常の言語、区切り線、主要先進国の言語（ドイツ / 日本 / 韓国 / イタリア / ポルトガル）、そして「その他の言語…」—— これを選ぶと残りを一枚に並べた小さなパネルが開きます。アラビア語とヒンディー語は今そこにいます。よく使う言語はスクロール不要で、後から追加した言語も自動的にそのパネルに入ります。

初回起動時の言語は次の順で決まる：

```
コマンドライン --lang=xx  >  システムの表示言語  >  英語
```

つまり中国語のシステムなら中国語、ロシア語 / フランス語 / スペイン語 / アラビア語 / ドイツ語 / ポルトガル語 / 日本語 / 韓国語 / ヒンディー語 / イタリア語のシステムならそれぞれの言語、それ以外は英語に落ちる（`pt-BR`、`zh-Hant`、`ar-EG` のような地域付き表記も認識する）。切り替えは今回の起動中だけ有効で、設定は保存されない。固定したいときは `Laocoon.exe --lang=ru` で起動する（その引数を付けたショートカットを作ればよい）。

翻訳されるのは画面だけではない。**レポート本文**も同じで、ラベル、章の見出し、ヒューリスティックな注意書き（「実行ファイルが一時フォルダにある」「このプロセスには非表示の最上位ウィンドウが他に N 個ある」）も現在の言語で生成される。

### アラビア語（右から左）の扱い

アラビア語は「文字列テーブルを差し替える」だけでは済まない。実測で 3 つの落とし穴が出た：

1. **画面の鏡像化**：フォーム全体を `RightToLeftLayout` で反転し、ツールバーは右から左へ並び、主要ボタンは右端に来る。
2. **レポートは鏡像化しない**：中身はパス、ハッシュ、ウィンドウクラス名といった技術データで、鏡像化すると各行の先頭と末尾が入れ替わって読めなくなる。レポート欄は常に左から右。アラビア語では**説明ページ**（散文）だけ右揃えになる。
3. **コロンがラベルの左に飛ぶ**：GDI の BiDi エンジンは「アラビア語ラベル + `:` + ラテン値」のコロンを右側の RTL セグメントに属すると判断し、`0 :المقبضx0001048E` のように描画する。対策はコロンの両側にゼロ幅の LRM（U+200E）を入れて向きを強制すること。書式引数（日付、PID、クラス名）にも同じ隔離を適用する —— そうしないと日付が `04:28:37 08-11-2026` になる。この書き方の比較実験は `--biditest` 診断に残してあるので、実装を入れ替えてもすぐ再実行できる。

**デーヴァナーガリー（ヒンディー語）**もアラビア語と同じく固定幅がないので、「スペースで埋めて桁を揃える」と余計に崩れる。この 2 言語ではレポートを `ラベル: 値` の形式に切り替え、揃っていないほうが揃ったふりをするよりまし、という方針にした。
アラビア語・ヒンディー語・日本語・韓国語はそれぞれ Windows が持っているフォント（Segoe UI / Nirmala UI / Yu Gothic UI / Malgun Gothic）を使い、入っていなければ自動でフォールバックする。豆腐や例外にはならない。

## 何を採るか

| 分類 | 内容 |
|---|---|
| ウィンドウ | ハンドル、クラス名、タイトル、スタイルビット（`WS_*` / `WS_EX_*` 名にデコード）、矩形、クライアント領域、可視 / 最小化、**最前面**、**ツールウィンドウ**、**DWM による不可視化**、オーナーウィンドウ |
| 命中したコントロール | 子コントロールまで正確に：クラス、コントロール ID、テキスト、ルートウィンドウからの階層パス |
| プロセス | PID / TID、フルパス、**コマンドライン**、親プロセス（名前 + PID）、アーキテクチャ（x86 / x64 / WOW64）、**昇格の有無**、セッション、起動時刻 |
| ファイル | サイズ、作成 / 更新日時、**MD5 / SHA1 / SHA256**、会社名、製品名、説明、ファイルバージョン、著作権 |
| デジタル署名 | 埋め込み署名の有無、署名者、発行者、有効期間、チェーン検証結果 |
| モジュール | そのプロセスが読み込んだ全 DLL のフルパス |
| 同一プロセスのウィンドウ | そのプロセスの**すべて**のトップレベルウィンドウ（非表示も含む、`[非表示]` 印つき）—— 望ましくないソフトの裏方ウィンドウはここから隠れられない |
| 子コントロールツリー | 対象ウィンドウの子コントロール全体。インデント、サイズ、ID、テキストつき |
| 疑わしい点のヒント | ヒューリスティック：Temp / ダウンロード / AppData にある、署名なし、会社名なし、最前面、非表示ウィンドウの数、7 日以内に作成されたファイル、など（**あくまでヒントで、断定ではない**） |

レポートは全体がプレーンテキストで、桁が揃い、章ごとに区切られている。全選択してコピーするか、「レポートを保存」で UTF-8 の `.txt` として書き出せる。ファイルをさらに確認したいときは、`sha256` を信頼できる任意のサービスへコピーしてほしい。このツールはローカルで採取するだけで、送信は一切しない（通信は「自動アップデート」のバージョン確認 1 回だけ）。

## 自動アップデート

新しい版のためにダウンロードページを探させるつもりはない。起動から数秒後、`1.7.0` より新しいものがあるかを GitHub に一度だけ問い合わせる。

- 読むのは公開されたテキストのマニフェスト 1 つ（`releases/latest/download/latest.txt`）だけ。版、ダウンロード URL、SHA-256、サイズ、日付、1 行の更新内容
- 端末の情報は**一切送らない**。デバイス ID も統計も「誰が使っているか」もない
- 新しい版があっても**ダイアログは出さない**。ツールバーに「更新 x.y.z」ボタンが 1 つ増え、ステータスバーが 1 行だけ言う。無視すれば二度と催促しない
- ダウンロードはそのボタンを押したときだけ。進捗バーと段階の表示、そして SHA-256 をその場で照合する。合わなければ削除する — 中途半端なファイルは絶対に入れない
- 照合が通ると小さな置換スクリプトを書き、終了 → exe を差し替え → 再起動。誰かが見張る必要はない
- 差し替えに失敗した場合（ウイルス対策がまだ掴んでいる、フォルダが読み取り専用）、スクリプトは旧版を起動しダウンロードページを開く。消えたプログラムを前に立ち尽くすことはない
- 確認自体の失敗（オフライン、遮断、社内プロキシ）は黙って飛ばす。他の機能はそのまま
- `--noupdate` で確認を完全に止め、`--feed=` で社内ミラーやローカルファイルに向けられる

マニフェストと exe は同じ CI の実行から出て、ハッシュもそこで計算される。「マニフェストは A、ダウンロードは B」という隙間は存在しない。


## 既知の制限

- **デジタル署名**は PE に埋め込まれた署名しか見ない。Windows 自身のファイル（`notepad.exe` など）はカタログ署名なので「埋め込み署名なし」と出るが、これは正常。
- 管理者権限なしで動かすと、昇格済み・保護されたプロセスからはパス / モジュール / コマンドラインが読めない（「権限不足」と表示）。それ以外の項目は通常どおり。
- コントロールのテキスト取得（`WM_GETTEXT`）は応答しないウィンドウに対して 60ms で打ち切る（`SMTO_ABORTIFHUNG`）。画面が固まらない代わりに、極めて稀なハングしたウィンドウではテキストが取れない。
- 子コントロールツリーは最大 240 件、モジュール一覧は最大 400 件。超えた分は「切り詰め」と明記される。
- ハッシュ計算は 512 MB まで。超えるとスキップする（待たされすぎないため）。
- 表示言語はシステムに従い、61 言語の外は英語に落ちる。翻訳は人手で書いており、`WS_*` / `WS_EX_*`、`DWM Cloaked` といった Windows 固有の用語はあえて英語のままにしている（言語ごとに勝手な訳語を作ると、かえって通じなくなるため）。
- アラビア語の画面は鏡像化するが、**レポートは常に左から右**。中身は技術データで、鏡像化すると読めなくなる。これは意図した設計で、翻訳の未完了ではない。

## 自分でビルドする

.NET SDK（8 以上）が必要。`build.bat` をダブルクリックするか：

```bat
dotnet build src\Laocoon.csproj -c Release
```

生成物は `src\bin\Release\net48\Laocoon.exe`。

> `build.bat` は `TEMP` を意図的にローカルの `.tmp` に向けている。システムの一時フォルダーに書き込めない環境ではビルドが即座に失敗するため。

## ソース構成

- `src/Laocoon.cs` — 本体。約 3191 行、すべて Win32 の P/Invoke で、NuGet パッケージは 1 つも使っていない
- `src/Lang.cs` — 言語の中核（列挙、判定、フォント、幅、取得、フォールバック）と 12 言語の表を 1 ファイルに。約 2762 行
`src/LangExtra.cs` — 操作 UI レベル 49 言語の文案（1 行 1 言語、38 項目）。約 120 行
- `src/Update.cs` — 更新モジュール。版の比較、マニフェストの解析、SHA-256 照合つきダウンロード、自己置換スクリプト、更新ウィンドウ。約 1195 行
- `src/Laocoon.ico` — ピクセルアイコン本体（16〜256 の 8 サイズ）。16 マスのグリッドから `tools/make_icon.py` で生成
- `docs/img/*.gif` — README に載せている 2 本のピクセルアニメーション。`tools/make_gifs.py` が 1 コマずつ描画（8 色、160×90 グリッド、整数倍拡大）

全量表は各 155 キー（操作 UI レベルの言語は 38 の中核キー）。すべて exe に埋め込む。`.resources` も satellite assembly も作らないので、どの Win10/11 マシンでもそのまま動き、「言語パックが無いので英語に戻る」ことは起きない。

主な入口：
- `Probe.HitTest` — z オーダーでトップレベルウィンドウを自分で走査してヒットテストする（`WindowFromPoint` を使わないので、自分のオーバーレイを掴まない）
- `Probe.DeepestAt` — `ChildWindowFromPointEx` で最内のコントロールまで降りる
- `Probe.Collect` — ウィンドウ / プロセス / ファイル / 署名 / モジュール / 兄弟ウィンドウ / 子コントロールツリーをまとめる
- `FrameForm` / `HudForm` — 照準時の透明な青枠と追従 HUD（どちらも `WS_EX_TRANSPARENT | WS_EX_NOACTIVATE` でマウスを奪わない）
- `L.T` / `L.F` — 文字列取得とプレースホルダー書式。欠けたキーは英語にフォールバックし、空欄にはならない

## 診断スイッチ（コードを触るとき用）

```
Laocoon.exe --selftest out.txt     コンソールウィンドウを採取し、レポートを表示してファイルに書き出す
Laocoon.exe --aimtest              ヒットテストと照準オーバーレイの自己診断
Laocoon.exe --i18ncheck            61 言語のキー欠落・列幅・フォント・方向を検査
Laocoon.exe --langswitch           全言語を順に切り替え、画面文言とレポートを照合
Laocoon.exe --focustest f.log [shot.png]  61 言語を順に切り替え、リストがフォーカスを保つか確認
Laocoon.exe --langstress 300 [log] [--rtl] キーリピートでの連続切り替えを再現し、ハンドル再作成と資源の安定性を確認
Laocoon.exe --biditest out.png     アラビア語 + ラテン文字の混在 8 パターン比較図（BiDi 検証）
Laocoon.exe --lang=ru              指定言語で起動（ini には書き込まない）
Laocoon.exe --uishot out.png --lang=ar            画面を PNG に描画
Laocoon.exe --uishot out.png --lang=ar --welcome  説明ページだけ描画
Laocoon.exe --uishot out.png --lang=ar --screen   画面キャプチャに切替（DrawToBitmap は RTL 欄に偽の選択範囲を描く）
Laocoon.exe --aboutshot out.png [--lang=xx]  「このアプリについて」を描画（アニメは数フレーム進む）
Laocoon.exe --langmenu out.png [--lang=xx]  開いた言語リストと第 2 レベルのパネルを撮影
Laocoon.exe --updatecheck [url|パス]  実際の確認を 1 回通し、版の比較結果を出力
Laocoon.exe --updatefetch url out.exe  ダウンロードして照合し、sha256 が一致するかを出力
Laocoon.exe --updateplan new.exe old.exe [page]  置換スクリプトだけを書き出し、パスとクォートを目視確認
Laocoon.exe --updateshot out.png [--lang=xx] [--state=dl|fail]  更新ウィンドウを描画
```

`--lang=` と組み合わせれば、61 言語の画面を一度に描画して目視確認できる。
